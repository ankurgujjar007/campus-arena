# Working style

- Answer first. Be concise, concrete, and free of filler, greetings, repeated summaries, and unnecessary narration.
- Use plain language and short sentences. Keep technical detail that affects correctness; never sacrifice clarity or accuracy for brevity.
- Inspect only the relevant files. Batch independent reads and tool calls, and do not reread unchanged content.
- Make the smallest complete change that solves the request. Preserve existing conventions and unrelated work.
- Report what changed and any important limitation. Run checks only when asked or needed to diagnose a reported failure.
